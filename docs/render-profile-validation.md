# v1.2.0 渲染规格修订与验证

## 后发甲方口径

2026-10-07，用户先转达“不需要光追，1080p，64采样”，随后明确Blender文件保留4K程度、视频可以1080p。现行标准1.1.0新增A20261007_RENDER：

- `.blend` 保存3840×2160 / 100% / Eevee / 64采样 / 光追false；竖片交换宽高。
- 实际导出帧1920×1080 / 100% / 64采样 / 光追false；在单独后台进程临时改渲染尺寸，不保存回工程。
- 原视频字节和分辨率不改；白模1080p，上下对比每幅1080p，总1920×2160；源帧率、帧数、源音轨同步保留。
- `render.width/height`与`render.output_width/output_height`分别锁定工程和导出规格，进入任务digest。默认profile是`client-4k-project-1080p`。
- CW071/CW074保留旧文、原来源、稳定ID及修订来源；133条记录/123条检查保留，其余131条规则记录不变。
- 4K设置只说明工程输出能力，不说明模型的动作/空间/光照质量已达标。低清预览依然只诊断，禁止把低清预览放大交付。

原版1.0.0与旧作业保留原完整Git pin。本版本不把旧作业的hash/通过位手动升级；client-4k/source-native历史profile用于明确指定的回归或旧口径诊断，不是当前制作默认。

## 实际验证范围

在真实Blender5.2上：

1. 独立打开4K、64采样、光追关闭工程；全帧物理检查与960×540预览、实际投影检查执行。
2. 实际双预检门禁后渲染全部3帧1920×1080 PNG，记录4K存盘工程尺寸和1080p渲染尺寸；保存工程SHA前后一致。
3. 独立重开原4K工程检查所有1080p PNG与清单；伪4K来源、误存1080p工程、光追仍开启均失败。
4. 真实4K/H.264/AAC合成参考保留原件；编码1080p白模和1920×2160上下对比；三MP4全解码、帧率/帧数及音频payload/PTS身份验证执行。
5. 真实队列租约以锁定输出规格复验全部PNG；检查4K工程来源、64采样与光追false，错误字段不能提交。

合成数值源观测不是客户动作真值。此验证说明改过的工具、像素尺寸、编码、工程保持与失败关闭有效，不代表任意客户视频复刻或Mac GPU已实测。Mac本机须运行[安装指南](mac-install.md)的真实Blender测试。
