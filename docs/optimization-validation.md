# 固定 SOP 提效模块验证范围

下文保留SOP最初验证的历史范围（当时规范1.0.0）；v1.2.0现行规范为1.1.0、4K工程/1080p导出/关闭光追，新增实际渲染编码回归见[规格修订验证](render-profile-validation.md)。

2026-10-07，本地候选分支 `codex/previs-pipeline-optimization`。规范版本仍1.0.0，133条/123条有效阻断和原件素材SHA不变。本页公开代码/隔离验证范围，不发布真实生产样片、逐帧制作报告或机器私有路径。发布状态以仓库tag/Release实际回执为准。

## 新增执行入口

- `pipeline.py`：代码、权重/显式输入、参数、依赖输出和job版本共同参与cache key；每次命中重新查实际产物SHA。失败帧段短承接、同主机真实attempt计时，不执行任意shell，不替制作程序解动作。
- `export_projection.py`：配置驱动、实际求值的全帧相机/骨端/刚性局部点/背景锚点导出，不保存/渲染；生产路径严格job pin，诊断路径明确不接生产门禁。投影不能声称像素遮挡已测。
- `render_preview.py`：一次Blender进程实际渲染全部分配帧，默认25%/16采样，同FPS/同范围；原工程仍保持原生规格和存盘字节。
- `match_check.py`：实际数值测量和覆盖校验，fit/holdout重投影、关节误差、幅度/峰值、可见性/遮挡顺序、背景残差幅相/相关性。哈希/完整PNG核验并重算，不信任passed位。
- `render_ready.py` / `render_native.py`：当前job与工程物理QA、当前数值预检共同通过才创建渲染输出。全原生渲染后再核验冻结证据，拒绝job映射/阈值变化后的旧QA。原生4K/100%/64采样与最终独立123条门禁继续保留。

## 测试分层

1. 数值测试：已知合成观测的误差/幅度/峰值/残差有预期数学结果；测试真实计算、证据SHA、PNG CRC/deflate结构、伪pass/旧场景/诊断晋级/缺观测等负例。源/工程字节为显式contract fixture，不把它称作客户复刻。
2. 阶段缓存测试：真实临时输入/代码/产物、键失效和计时；明确隔离special validator的mock测试与委派/失败关闭测试。验证缓存复用，不表示泛化解算已验证。
3. 新实际Blender链路：真实干净临时Git提交、3帧4K H.264参考、十部件真实绑定工程、实际物理检查、全3帧960×540预览、全3帧3840×2160原生渲染。source-match数值是明确的合成契约，不是从纯色参考观测出的真实姿态。验证CLI和双预检阻断，不验证客户动作匹配。
4. 新投影负例：生产模式实际骨端投影，投影可见性保持unknown；缺骨、错误相机、源SHA、动画背景、米单位错误和相机marker切换应阻断，不写伪完成产物。诊断与生产模式分别验证。
5. 原有真实Blender/HTTP SQLite/媒体CFR/门禁/安装/素材测试全量回归，真实Blender缺席明确skip。

## 衡量提效，保持验收边界

性能报告分开记录：JSON字节/读取解析、只读投影、各stage真实attempt、低清预览、4K渲染、独立审查与返工。不把warm-cache读取提速当端到端制作加速；不从一个场景外推30,000分钟产能。对真实当前10秒候选的诊断仍在制作工作区保存，缺观测和已失败的空间/动作匹配继续待整改，未填甲方签收。

没有导入未经测试的新视频动作网络、商业受限权重或未经验证的GPU环境。现阶段优化是少重复计算、减少Agent读大报告、先量化和阻断错误再消耗4K渲染，而不是降低动作、运镜或光照标准。
